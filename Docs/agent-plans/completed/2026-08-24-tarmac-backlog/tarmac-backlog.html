Tarmac Backlog

Generated 2026-08-24

Tarmac today is a single hardcoded search: one form in the sidebar, one set of results, one route. This backlog captures the shift to a multi-search app — searches are created, saved and revisited from the sidebar, each one keeping its own history of results so price movement over time becomes visible. Configuration moves out of the search UI and into a proper Preferences window.

Backlog

  1. Move the API key into a Preferences window

    The Ignav API key currently sits at the top of the sidebar search form, mixed in with the trip parameters. It belongs in a standard macOS Preferences window, reachable from the application menu with ⌘, — configured once and then out of the way, rather than re-presented on every search.

  2. Turn the sidebar into a history of saved searches

    Replace the sidebar form with a list of the searches that have been set up. Each row describes its own search — date, destination, and the other parameters that define it — so a search can be recognised at a glance.

    Selection is exclusive: exactly one row is selected at a time, and selecting a row drives the right-hand panel to show that search and its results.

  3. Create new searches from a “+” button in the sidebar

    A “+” button in the sidebar starts a new search. It opens a modal sheet over the main window for entering the search parameters described in the items below.

  4. Choose one-way or round trip first

    The first thing the new-search sheet asks is which kind of best-price search to run: the cheapest one-way flight, or the cheapest round trip. That choice determines which set of options is presented next — the two differ substantially.

  5. One-way search options

    A one-way search is defined by:

    • Origin and destination — IATA codes
    • Date range — the window to search for the best price within
    • Cabin class — business, etc.
    • Direct flights only — checkbox
    • Luggage included (soute) — checkbox

  6. Round-trip search options

    A round trip is not just two one-way searches: the search is over trip shapes, not fixed dates. It is defined by:

    • Origin and destination — IATA codes
    • Date range — the window to search for the best price within
    • Trip duration — the number of days to be away
    • Flexibility — ± a number of days around that duration
    • Must include the weekend — checkbox; with a 3-day trip, Monday-to-Wednesday is then not an option
    • Cabin class — business, etc.
    • Direct flights only — checkbox
    • Luggage included (soute) — checkbox

  7. Refresh button on the results panel

    The right-hand panel shows the results of whichever search is selected in the sidebar, with a refresh button to re-run that search on demand and pull current prices.

  8. Keep a history of result runs in the main view

    The right-hand panel keeps every result run for the selected search, not only the most recent one. Successive refreshes accumulate, so the price movement for that search over time is visible rather than overwritten.
